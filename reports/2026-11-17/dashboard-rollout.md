# Dashboard rollout tracker

The redesign standard set by **Quotation & SO Tracker** and **CEO Command Centre** is applied to every dashboard, one at a time, with each dashboard's content verified against the ERP map.

Scheduled runs and manual sessions resume from this file. Pick the first row whose status is `todo` or `in progress`, follow the procedure, and update the row before moving on.

Status values: `todo` · `in progress` · `done` · `blocked (reason)` · `excluded (reason)`

## Procedure (every dashboard)

1. **Inspect.** Read `dashboard.js`, `dashboard.css`, `dashboard.html`, `README.md` and `server_scripts/*.py`. List every DocType and field the dashboard reads or writes, including fields inside server scripts.
2. **Verify against the ERP map** (`.local/erp-map/erp-map.json`, 1,684 DocTypes). For each source, check:
   - the DocType and fields exist, with the right types (Date vs Datetime, Currency, Link targets);
   - whether it is submittable (drafts and cancelled excluded where it matters);
   - that `company` is a Link where filters use it.

   Record broken or guessed fields, and record widgets that are not useful to the reader: vanity counts, undefined metrics, totals across currencies, zeros shown for failed sources. Fix them; don't keep them.
3. **Redesign to the shared standard.** Reuse the patterns, tokens and code shapes of the two reference dashboards:
   - **Toolbar:** title and status, then (right to left in English) language `English | العربية`, refresh, filters popover (searchable), period selector with presets and a calendar, and a pending-actions count.
   - **Tabs:** browser-style tabs on a connected sheet. Keep every existing section.
   - **KPI cards:** 4–6 per overview, from real data only. Sparklines and deltas only when a real series or comparison exists.
   - **Actions pending section (required on every dashboard):** the most urgent real records ranked, each linking to its ERP record, with responsible person, due date or age, a priority label, per-category counts with "view all", and loading, empty and error states. Use the dashboard's own follow-up data; respect permissions.
   - **Charts:** ranked bars and share lists instead of crowded pies, monthly bars, tooltips. Charts follow the global filters.
   - **Platform:** container queries; touch targets of 44px or more on coarse pointers; no horizontal overflow down to 320px; Arabic RTL; Desk dark mode; reduced motion.
   - **Business logic:** keep existing data logic, APIs, permissions and write behaviour unless they are wrong (then fix and note).
4. **Shared shell.** If the dashboard is now built on the standard directly, remove it from `tools/erp/shell/shell_map.json` (entry and `_dark`, plus the i18n list if present) and run `npm --prefix tools/erp run test:shell`.
5. **Test.** Write `tools/erp/tests/<slug>-browser.cjs` with a fixture-backed mock of the APIs it calls (pattern: `quotation-tracker-browser.cjs`, `ceo-command-center-browser.cjs`).
   - **Assert:** figures against the fixture, filters, period, actions-pending links, every tab, and EN and AR at 3440, 1440, 768, 375 and 320px, with no overflow and no page errors.
   - **Screenshots:** save to `.local/qa/<slug>/` and look at them; fix what looks wrong.
   - **Other suites:** run `npm --prefix tools/erp test` and the collector or server tests that apply. Server Scripts must follow the live sandbox rules: no tuple-unpacking assignment and no augmented assignment.
6. **Document.** Add a dated section to the dashboard `README.md`: what changed, which fields to paste on deploy, and any Server Script change. Mark the row `done` here, with one line of notes and the test count.

**Never:** commit, push or deploy; write to the live ERP; invent data. Don't discard other people's uncommitted work: FM & Inventory has an earlier uncommitted v5; align it, don't replace it blindly.

## Shared kit (from row 3)

Dashboards on the standard embed `tools/erp/kit/dms-kit.js` and `dms-kit.css` between "DMS kit" markers (Custom HTML Blocks must be self-contained). Edit the kit, run `python tools/erp/kit/build_kit.py`; `test:shell` fails if any copy is stale. Browser tests use `tools/erp/tests/dms-harness.cjs` (fixture mock, toolbar, tabs, RTL, dark, responsive sweep, denied sources, empty state).
